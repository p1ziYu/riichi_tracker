# Engine porting decisions

Source: `packages/engine/src/index.ts`, SHA-256 `e17744271610b2a82b0825c8ca4bfa7aa4604ccbdb5577cefc032a2d9b003df4` (engine version `0.1.0`). The port deliberately preserves engine behavior, including behavior that differs from prose comments.

- `markRevision` and `resultRevision` are TS `bigint`; Kotlin uses `Long`. They are revision counters, not scores; the JVM fixture decoder reads tagged `$type: bigint` values losslessly into `Long`. No settlement calculation uses these counters.
- Stored balances, pool, hand transfers, and score tenths are bounded to signed 32-bit storage by the TS engine. Intermediate sums/products use `Long` or `Double` where TS arithmetic can exceed `Int`; validate at the same `safePoints`/`validStoredInteger` boundaries rather than wrapping. `uma` and `oka` remain fractional decimal values (`Double`) because normalization accepts finite numeric inputs, including fractional tenths that must be rejected only at the engine's validation boundary.
- TS `Math.ceil(points / 100) * 100` for point rounding is ceil division, including negative inputs. Fu rounds up by tens except exactly 25 fu. Non-dealer compensated 3p tsumo divides the full four-player total by 3 and rounds the non-dealer's share *up* to 100; dealer compensated tsumo divides by 2 and rounds the first share *up* to 100. The other share is the remainder, not independently rounded.
- TS `Math.floor(total / tieCount)` for a tied uma group must use floor division, **not** Kotlin integer `/` when the sum is negative. Distribute positive remainder in stable rank order after floor division. TS `%` has the sign of its dividend; Kotlin `rem` matches, while Kotlin `mod` does not. Rotation-distance modulo has non-negative operands after adding the player count. Honba divisibility, noten divisibility, pool multiple, and manual payment multiple use remainder, not modulo.
- TS `Math.round(x)` breaks half ties toward positive infinity (including negative halves); Kotlin `roundToInt()` uses a different tie rule. The port uses floor(x + 0.5) where needed: normalization of uma and oka tenths, terminal uma/oka tenths, and `baseTenths` from `(finalPoints - returnPoints) / 100`. Integer points in terminal outputs are multiples of 100, so base tenths normally divide exactly. `competencyPoints = totalTenths / 10` is a floating decimal number, not integer division.
- TS basic points use `fu * 2^(han+2)` below limit brackets; compute the same power and apply the 2,000 cap and kiriage 1,920 exception at the same branch. Ordinary yakuman and special doubles are counted separately before the composite cap; fu is checked even for yakuman if supplied.
- TS nullish coalescing (`??`) treats absent/undefined/null as absent, but `pickNumber`/`pickBoolean` first check own-property presence and reject null/undefined or wrong type. The first present alias wins even if invalid. Template lookup only recognizes exact keys; an unknown `templateKey` remains in output while defaults come from player count. Invalid enum options fall back, not fail; `tsumoPaymentMode` string overrides `tsumoLoss`; legacy kazoe spelling overrides its boolean parser. Preserve these distinctions in raw configuration maps.
- Explicit `uma` wins over `umaTenths` when it is an array; non-array values are ignored. Explicit `oka` and `okaTenths` are consistency checks against computed oka, not independent settings. Honba fields resolve through top-level aliases, then nested object aliases, then numeric legacy `honba`; one explicit half determines the other, with divisibility checked before defaults.
- Per-seat payment arrays and terminal `perSeat` preserve **input** seat order. Settlement dealer rotation and multi-ron winner priority use separately sorted seat numbers. Tsumo payer iteration uses sorted seat numbers. `tenpai[i]` refers to `handState.seats[i]`, not sorted order. Terminal `standings` is rank order, with stable starting-dealer-distance tie order.
- In a multi-winner nagashi, pool collection uses `resultInput.winners[0]` exactly, even though the engine's comment describes turn order. Nagashi pays each winner as tsumo mangan and omits honba payment; its dealer-repeat flag may use dealer tenpai instead of winning status. Chombo exits before riichi deductions and the zero-sum assertion; manual payment entries follow object iteration order.
- End decision uses raw points before pool allocation; provisional rank decides first-place pool recipient; final rank uses pool-adjusted points. A continuing match returns only the three point fields for each seat, with empty standings/tenths. Tied uma splitting awards indivisible tenths in final ranking order, and rank numbers can be shared; oka still goes only to first sorted seat. The terminal invariant accounts for unallocated pool in tenths.
- `HandKind` is an enum with the exact five wire strings; a string-bearing `ResultInput` boundary still lets unknown kinds reach the TS unsupported-kind check. Terminal input variants cover numeric arrays, seat arrays, mixed numeric/seat arrays, and objects with inline options. Terminal output is a sealed ended/not-ended union so a continuing seat has no score fields. Raw overloads preserve malformed JSON inputs for the differential gate.
- `EngineException` with `ENGINE_VALIDATION` represents TS `Error` from engine checks; `HOST_TYPE` represents native `TypeError`/`RangeError` when applicable. The fixture gate checks the mapped throw category (and also checks the frozen error text). Tagged JSON encoding is test-only, outside commonMain.
